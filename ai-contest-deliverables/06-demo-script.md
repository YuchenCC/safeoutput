# Safe Output 竞赛演示脚本

## 1. 文档定位

本文是一份 3 到 5 分钟竞赛演示脚本，用于后续人工审核、录屏剪辑或使用 HyperFrames 制作视频。脚本重点展示 Safe Output 如何面向 Java 8 / Spring Boot 2.x 老系统，以 starter 方式覆盖 Response、Log4j2 日志、主动脱敏、风险统计、报告和 Dashboard。

演示主线：

```text
老系统敏感输出痛点
  -> Safe Output 组件能力
  -> 低侵入接入方式
  -> Response 自动脱敏
  -> API ignore 明文风险可统计
  -> 日志脱敏与规则建议
  -> 主动脱敏实验室验证
  -> Dashboard / 报告沉淀治理结果
```

本脚本中的明文展示只允许使用 Demo/mock 样例，不使用真实用户数据。正式视频中如出现 raw 明文演示画面，建议短暂停留或局部打码，并用字幕标注“Demo mock 数据”。

## 2. 演示准备

启动命令：

```powershell
cd safe-output
mvn -pl safe-output-demo -am spring-boot:run
```

浏览器入口：

- Demo 工作台：`http://localhost:8080/index.html`
- 独立治理 Dashboard：`http://localhost:8080/safe-output/dashboard/index.html`

建议演示前先操作一次客户详情、raw 查看、脱敏实验室和报告导出，让 Dashboard 中已有可观察的聚合数据、ignored API 和日志建议。

## 3. 分镜脚本

### 场景 1：老系统敏感输出痛点

| 项目 | 内容 |
|---|---|
| 时间段 | 0:00 - 0:25 |
| 场景目标 | 先说明为什么输出侧脱敏不是一个简单工具函数，而是老系统治理问题。 |
| 画面内容 | 使用一张“老系统敏感输出风险图”。画面中心是一个标注为“Java 8 / Spring Boot 2.x 老业务系统”的应用框，右侧分出四条输出路径：`Response`、`Log4j2 日志`、`导出报告`、`跨系统调用`。每条路径旁用标签标出“手机号”“证件号”“邮箱”“地址”“密码”等敏感字段。底部放三条风险提示：“人工梳理容易遗漏”“分散脱敏维护成本高”“日志和报告容易成为新泄露点”。 |
| 演示操作 | 无浏览器操作，使用静态图或轻量动画。 |
| 操作反馈结果 | 观众能看到敏感数据不是只出现在数据库里，也会通过接口、日志和报告离开系统。 |
| 讲解词 | “在很多 Java 8 老系统里，敏感信息不仅存在于数据库，还会从接口 response、业务日志、导出报告和跨系统调用中输出。靠人工梳理字段和接口很容易漏，靠每个 Controller 手写脱敏又很难长期维护。Safe Output 解决的是输出侧治理问题。” |
| 图/转场说明 | 图应为浅色架构图，不出现真实敏感值，只出现字段类型标签。转场从风险路径收束到中间的组件框，为下一场组件能力做铺垫。 |

### 场景 2：组件功能描述

| 项目 | 内容 |
|---|---|
| 时间段 | 0:25 - 0:50 |
| 场景目标 | 用一张能力图说明 Safe Output 的定位和闭环，不先进入代码细节。 |

| 演示操作 | 无浏览器操作，使用静态图或流程动画。 |

## 4. 操作反馈结果清单

演示过程中需要明确说出的可观察反馈：

- 工作台总览展示 starter、YAML rules、注解、字段 ignore、API ignore 等接入方式。
- 客户或支付详情中，敏感字段已脱敏，业务编号保持可读。
- raw 明文查看只用于 Demo/mock 演示，真实接入中必须保护入口。
- raw/API ignore 命中后会进入 ignored 风险统计。
- 日志场景显示 `LOG 脱敏计数`，说明真实 Log4j2 输出链路已被统计。
- 日志规则建议默认 `enabled:false`，不会自动改写配置。
- 脱敏实验室返回两轮结果，第二轮稳定，展示主动脱敏幂等性和耗时。
- Dashboard 实时数据和历史报告只展示聚合信息，不保存敏感原文。

## 6. 安全边界口径

演示中不要声明以下能力已经实现：

- Spring Boot 3.x 已验证支持。
- WebFlux、Logback 或完整 JSON Parser 日志解析。
- Dashboard 自带登录、权限、审计、多租户或公网防护。
- 报告数据库持久化。
- 规则建议自动采纳、自动写 YAML 或自动启用。

必须强调的边界：

- Safe Output 当前主要面向 Java 8 / Spring Boot 2.x。
- Response、对象递归、日志和报告异常都坚持 fail-open，避免影响业务主链路。
- 报告、Dashboard 和规则建议不保存原始 response、完整日志或敏感值。
- Dashboard 是可选附加包，真实业务启用后应由接入方通过内网、网关或 Spring Security 等方式保护入口。
