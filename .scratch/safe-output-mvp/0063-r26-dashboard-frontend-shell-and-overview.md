## What to build

把 Dashboard starter 当前最小静态页面升级为可复用治理前端的基础壳层，并完成实时概览与接口风险两个核心页面的可扫描布局。

页面继续由 `safe-output-dashboard-spring-boot-starter` 随包提供，不引入前端构建链，不依赖 Demo 静态资源或 Demo API。前端通过统一 `SafeOutputDashboardApi` 调用 `{path-prefix}/api/...` POST API，左侧固定导航包含实时概览、接口风险、日志建议、历史报告和脱敏实验室。

实时概览首屏必须展示页面标题、刷新动作、当前状态和至少四个关键指标；接口风险页以聚合表格为主，清晰区分高风险接口、ignore 接口和慢接口。页面只展示聚合指标、接口路径、类型标签、风险标签和必要摘要，不展示原始 response、完整日志 message 或敏感命中值。

## Acceptance criteria

- [x] Dashboard starter 前端保留独立入口 `/safe-output/dashboard/index.html`，支持默认路径前缀和自定义路径前缀下的静态资源加载。
- [x] 左侧固定导航与 hash 路由覆盖 `#overview`、`#risk`、`#log-suggestions`、`#reports`、`#lab`，当前路由有明确选中态。
- [x] 前端治理数据调用统一经过 `SafeOutputDashboardApi` 或等效 API 层，不在页面逻辑中散落裸 `fetch`。
- [x] 页面不调用 `/demo/report/**`、`/demo/mask/**` 或任何 Demo 业务接口。
- [x] 实时概览页展示总脱敏次数、Response/Log/Manual 场景计数、失败次数、平均耗时和最大耗时中的至少四项关键指标。
- [x] 实时概览页展示场景分布、类型 Top、高风险接口摘要、日志建议摘要和性能/异常拆解；图表可用轻量 Canvas、条形图或表格替代。

- [x] 刷新、加载、空数据和请求失败状态可诊断，不破坏页面整体布局。
- [x] 页面和 API 展示内容不包含原始 response、完整日志 message、敏感命中值或 Demo raw 明文字段。
