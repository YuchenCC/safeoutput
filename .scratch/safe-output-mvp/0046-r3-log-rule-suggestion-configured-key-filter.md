## What to build

报告导出、Dashboard 和 Demo 日志建议接口在生成 Log 规则建议时，应传入当前 `safe-output.rules[].keys` 作为已配置 key 集合，避免对已经配置过的日志字段重复生成治理建议。正常 Log4j2 在线采集仍保持轻量；报告阶段只做基于聚合线索和配置 key 的过滤，不保存完整日志或敏感原文。

## Acceptance criteria

- [x] `MaskReportExporter` 生成 `logRuleSuggestions` 和 `configSnippet` 时过滤已配置 key。
- [x] `/demo/report/log-suggestions` 过滤已配置 key。

- [x] 已配置 key 的成功日志脱敏仍计入 `LOG` 场景统计和类型分布。
- [x] 报告、Demo 接口和 JSON 快照不包含完整日志、敏感原文或 raw value。
- [x] 现有 `LogRuleSuggestionAnalyzer.analyze(metrics, configuredKeys)` 语义保持兼容。
