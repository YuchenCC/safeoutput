## What to build

完善 Dashboard starter 的日志建议和历史报告页面，把当前 JSON 直出式展示改为面向治理复核的聚合可视化。

日志建议页展示建议 key、建议类型、命中次数、置信度、脱敏 evidence 摘要和默认 `enabled:false` 的 YAML 候选片段，保持“人工复核后启用”的语义，不提供自动采纳按钮。

历史报告页包含报告文件列表、单报告详情和上传报告临时查看。报告列表展示文件名、大小、修改时间和可查看状态；单报告详情和上传报告结果复用同一套可视化模型，展示总览指标、场景分布、类型 Top、高风险接口、ignore 风险接口、日志规则建议和性能指标。页面不得展示 JSON 报告原文。

## Acceptance criteria

- [ ] 日志建议页展示建议 key、建议类型、命中次数、置信度和 evidence 摘要。
- [ ] 日志建议页展示默认 `enabled:false` 的 YAML 候选片段，并明确人工复核后再启用。
- [ ] 日志建议页不提供自动采纳、自动修改 YAML 或在线规则热更新入口。
- [ ] 历史报告页展示报告文件名、大小、修改时间和可查看状态。
- [ ] 报告查看通过 POST body 传递文件名，不把文件名放入 URL path 或 query string。
- [ ] 单报告详情展示总览指标、Response/Log/Manual 场景分布、类型 Top、高风险接口、ignore 风险接口、日志规则建议和性能指标。
- [ ] 上传报告临时查看与历史单报告详情复用同一套聚合可视化模型。
- [ ] 上传报告不在前端制造上传历史，不把上传结果加入报告目录列表。
- [ ] 页面不得使用 JSON 原文 `<pre>` 作为报告详情或上传结果的主要展示方式。
- [ ] 页面不展示 JSON 报告原文、原始 response、完整日志 message、敏感命中值或 Demo raw 明文字段。
